# 手工验收清单 —— Computer-Use

`tests/unit/` 在 CI 跑，`tests/native/` 在本机跑。**本清单是人眼验收**：
那些只有真人看着屏幕才能判断的项，以及设计阶段遗留、至今没有实测结论的项。

跑法：逐条执行，把结论填进「结论」列。允许的结论只有三种：
`通过` / `失败` / `不适用（理由）`。**不许留空** —— 留空就是没验收。

## 1. 输入封锁与逃生（最高风险，必须人眼过一遍）

这一节错了的后果是把用户锁在电脑外。**必须在真人坐在机器前时做。**

| # | 项 | 怎么验 | 期望 | 结论 |
|---|---|---|---|---|
| 1.1 | 物理键在封锁期间被吞 | `desktop_smoke.py --blocking`，封锁期间按任意字母键 | 目标应用**收不到**该字符 | |
| 1.2 | 物理 Esc 中止并解除封锁 | 同一脚本，按物理 Esc | 脚本立刻继续，键鼠立即恢复 | |
| 1.3 | 注入输入在封锁期间被放行 | 同脚本自动做（发 F24 并确认未被吞） | 注入事件正常送达 | |
| 1.4 | 脚本异常退出后输入恢复 | 封锁期间用任务管理器杀掉 python 进程 | 键鼠立即恢复（钩子随进程死亡被 OS 摘除） | |
| 1.5 | Ctrl+Alt+Del 始终可用 | 封锁期间按 Ctrl+Alt+Del | 安全界面出现（用户态钩子拦不住它） | |
| 1.6 | 钩子超时后封锁静默失效可被察觉 | 人为让钩子回调变慢（如加 `time.sleep(1)`）后按键 | 输入恢复；daemon 日志有记录 | |

> 1.1 / 1.2 是本项目安全设计的**唯一实测入口**。Q-018 的物理侧至今未实测，
> 正是因为之前的 spike 没有人手配合。这几条不通过，覆盖层与封锁功能不得发布。
